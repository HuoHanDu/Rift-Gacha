# 随机规则规范（实现权威）

本文是随机算法的**唯一权威规范**。`AGENTS.md` 只描述需求意图；需求与本文冲突时以本文为准。
所有 ID 均指数据快照中的官方 ID（见 `docs/DATA.md`）。版本口径：**16.18**。

## 1. 输入模型与校验

```ts
type Position = 'top' | 'jungle' | 'mid' | 'adc' | 'support'

interface PlayerInput {
  name?: string            // 选填，空白则显示「玩家 N」
  position?: Position      // 选填，留空表示随机
  team?: 1 | 2             // 仅十人双队模式使用
}

interface GenerateInput {
  players: PlayerInput[]
  teamMode: boolean            // false = 单队(1~5人)，true = 双队(最多10人)
  splitTeamsRandomly: boolean  // 双队模式下：是否随机分队
  banSmiteForNonJungle: boolean // 默认 true
}
```

**校验规则**（全部在生成前完成，失败返回结构化错误而非抛异常）：

| 编号 | 规则 | 错误码 |
| --- | --- | --- |
| V1 | `players.length ≥ 1` | `NO_PLAYERS` |
| V2 | 单队 `players.length ≤ 5`；双队 `≤ 10` | `TOO_MANY_PLAYERS` |
| V3 | `teamMode && !splitTeamsRandomly` 时每个玩家必须已指定队伍 | `MISSING_TEAM` |
| V4 | 预先分队时每队 `≤ 5` 人 | `TOO_MANY_PER_TEAM` |
| V5 | 同一队内不得出现重复位置（预先分队时静态判定；随机分队时在「发牌」阶段判定） | `DUPLICATE_POSITION` |
| V6 | `players.length ≤ 英雄池容量` | `NOT_ENOUGH_CHAMPIONS` |

**单队模式**：已指定的位置先占位；其余玩家从「5 个位置 − 已占」里洗牌后依次补齐（人数 < 5 时只取所需个数）。

**双队模式 + 随机分队**：为保证「每队 5 个位置互不重复」，不能简单地「洗牌后前 5 人一队」——那样很容易出现某队两个上单。实际做法是**发牌**：

1. 打乱玩家顺序（这就是随机性的来源）。
2. 队伍容量为 `ceil(n/2)` 与 `floor(n/2)`。
3. 按打乱后的顺序逐个玩家发牌，候选队伍必须同时满足「还有空位」且「没有同位置的队友」；在候选里优先发给当前人数少的一队，并列时随机。
4. 发不到的（例如 6 个人都要上单）返回 `DUPLICATE_POSITION` 并说明原因——这种输入本身无解。
5. 未指定位置的玩家先占位，之后再从各队剩余位置里洗牌补齐。

**双队模式 + 预先分队**：按 `player.team` 分组，每队独立做与单队模式相同的分配。

**未指定队伍的玩家兜底算 1 队**（正常流程下 V3 会先拦下来）。

## 2. 位置分配算法

对**每一队**：

1. 收集该队中已指定位置的玩家，写入 `taken` 集合。若某个位置被指定两次 → 触发 V5。
2. `freeSlots = POSITIONS − taken`，洗牌。
3. 该队未指定位置的玩家按顺序从 `freeSlots` 依次取用（取所需个数即可，队伍不满 5 人时不会取完）。

随机分队模式下，「分队」与「位置分配」是同一个发牌过程，见 §1。

位置与玩家绑定后，后续所有随机都以「玩家 = 位置」为准。

## 3. 英雄

- 池：快照中全部英雄（16.18 共 **173** 个），不做位置过滤（任何英雄都可能出现在任何位置）。
- **全场去重**：维护全局 `usedChampions: Set<heroId>`，抽取前从池中剔除已用英雄，再等概率抽 1，抽中后写入集合。
- 单人模式同样走这条路径（集合初始为空）。

## 6. 符文

### 6.1 五系

| 系 ID | 名称 | 基石数 | 系内小符文排数 |
| --- | --- | --- | --- |
| 8000 | 精密 | 4 | 3（英武 / 战斗 / 传说） |
| 8100 | 主宰 | 3 | 3（预谋 / 追踪 / 狩猎） |
| 8200 | 巫术 | 4 | 3（宝物 / 卓越 / 威能） |
| 8300 | 启迪 | 3 | 3（巧具 / 未来 / 超越） |
| 8400 | 坚决 | 3 | 3（蛮力 / 抵抗 / 生机） |

### 6.2 主系

1. 从 5 系中随机 1 系。
2. 从该系基石中随机 1 个（`keystone`）。
3. 该系 3 排系内小符文**每排随机 1 个**（`primaryMinors`，共 3 个）。

### 6.3 副系

1. 从「5 系 − 主系」中随机 1 系（**必须与主系不同**）。
2. 从该系 3 排中**随机选 2 排**（不重复）。
3. 每排随机 1 个（`secondaryMinors`，共 2 个）。

**符文页总计 = 1 基石 + 3 主系小符文 + 2 副系小符文 = 6 个。**

### 6.4 三个小符文（属性碎片）

每排随机 1 个：

| 排 | 候选 |
| --- | --- |
| 进攻 | `5008` 适应之力、`5005` 攻击速度、`5007` 技能急速 |
| 灵活 | `5008` 适应之力、`5010` 移动速度、`5001` 成长生命值 |
| 防御 | `5011` 生命值、`5013` 韧性和减速抗性、`5001` 成长生命值 |

> 注意 `5008` 与 `5001` 各自出现在两排中，两排独立随机，允许结果相同（这是官方行为）。

### 6.5 海克斯科技闪现罗网约束

- 该符文位于**启迪系「巧具」排**，ID `8306`，同排为 `8304` 神奇之鞋、`8321` 返现。
- **可被随机到的充要条件**：召唤师技能含 `4` 闪现 **且**（主系 = 启迪 **或** 副系 = 启迪）。
- 实现方式：在「巧具」排执行随机时构造候选集 —— 条件满足 ⇒ `{8306, 8304, 8321}`；条件不满足 ⇒ `{8304, 8321}`，再等概率抽 1。
- 该约束只作用于「巧具」排；启迪系其余两排（未来 / 超越）与是否含闪现无关。
- **时机**：召唤师技能必须在本步骤之前生成完毕（生成顺序：位置 → 英雄 → 召唤师技能 → 装备 → 符文）。

## 7. RNG 与可复现性

```ts
type Rng = () => number   // 返回 [0, 1)

pick<T>(arr: T[], rng: Rng): T
pickMany<T>(arr: T[], n: number, rng: Rng): T[]   // 无放回
shuffle<T>(arr: T[], rng: Rng): T[]
```

- 引擎只接受注入的 `rng`，默认实现为 `Math.random`。`src/components/`、`src/pages/` 内**禁止**出现 `Math.random()`。
- 多人生成按 `players` 数组顺序串行，共享同一个 `rng` 实例与 `usedChampions` 集合。
- 因此：**同一 seed + 同一快照 + 同一输入 ⇒ 逐字节相同的结果**。测试和「复现这一次随机」都依赖这条性质。
- 种子 RNG 用 `mulberry32` 之类的短小实现，不引第三方依赖。

## 8. 生成顺序（单次结果的确定性流水线）

```
位置分配
  → 英雄（全局去重）
  → 召唤师技能（依赖位置）
  → 出门装（依赖位置）
  → 六件成装（无放回）
  → 鞋子（依赖位置：中路升级）
  → 主系（系 → 基石 → 3 个系内小符文）
  → 副系（系 ≠ 主系 → 2 排 → 每排 1 个）
  → 三个小符文（3 排各 1 个）
```

召唤师技能先于符文，是 §6.5 约束成立的前提。

## 9. 输出模型

```ts
interface BuildResult {
  playerIndex: number
  name: string
  team: 1 | 2
  position: Position
  champion: { heroId: string; name: string; alias: string; title: string; roles: string[] }
  spells: [SpellRef, SpellRef]
  starterItem: ItemRef
  /** 仅辅助非空：云游图鉴的升级件 */
  displayStarterItem: ItemRef | null
  legendaryItems: ItemRef[]      // 长度 6
  boots: ItemRef                 // 中路为升级款
  runes: {
    primaryStyle: StyleRef
    keystone: RuneRef
    primaryMinors: RuneRef[]     // 长度 3
    secondaryStyle: StyleRef
    secondaryMinors: RuneRef[]   // 长度 2
  }
  shards: RuneRef[]              // 长度 3，顺序固定为 进攻 / 灵活 / 防御
}
```

`ItemRef` / `RuneRef` / `SpellRef` / `StyleRef` 只携带渲染与资料卡所需的字段（id、名称、图标 URL、说明文本、价格等），由快照裁剪而来。

## 10. 断言与边界用例（`tests/` 必须覆盖）

| 用例 | 期望 |
| --- | --- |
| 打野 | 两个召唤师技能中必含惩戒 |
| 非打野 + 开关开 | 不出现惩戒 |
| 非打野 + 开关关 | 允许出现惩戒 |
| 任意结果 | 两个召唤师技能不重复 |
| 成装 | 恰好 6 件，互不重复，全部来自 107 件传说池 |
| 成装 | 不含任务专属 6 件，不含鞋子 |
| 鞋子 | 非中路为未升级 7 双之一；中路为 7 个升级款之一 |
| 符文 | 副系 ≠ 主系；主系小符文 3 个分属 3 个不同排；副系小符文 2 个分属 2 个不同排 |
| 符文 | 若出现 `8306`，则召唤师技能必含闪现且启迪为主系或副系 |
| 符文 | 若不满足条件，`8306` 永不出现在任何位置的候选结果中（用固定 seed 扫描全部 seed） |
| 小符文 | 每排结果属于该排候选集 |
| 多人 | 英雄全场不重复；装备跨玩家可重复 |
| 双队 | 每队位置恰好覆盖 5 个不同位置 |
| 双队 + 指定位置 | 指定的位置被尊重，其余随机补齐且不冲突 |
| 可复现 | 同 seed 同输入两次运行结果深比较相等 |
| 输入校验 | 人数/位置数不等、同队重复位置 → 返回结构化错误 |
